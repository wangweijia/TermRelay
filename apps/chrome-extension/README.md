# 网页上下文 AI 对话与局域网预览插件

业务页面使用纯对话图标作为入口，不展示产品名称；定位是围绕当前网页与 AI 交互，而不只是提交修改任务。
可以提问实现逻辑、讨论交互、分析问题，也可以明确请求修改；页面、元素和截图是可选的对话上下文。
消息自动进入绑定的 TermRelay 本地普通 ACP 会话，插件显示处理状态、AI 答复，并支持继续追问。
只有明确要求修改时才引导 AI 改动代码；问答不进入强制验收，不要求预先选择问答 / 修改模式。
不自动采集图片，不新建 AI 会话，插件和桥接不直接操作 CLI，不依赖 TermRelay Server 或修改远程通信协议。

```text
直接访问（默认）：业务方 Chrome -> 项目原地址（局域网 IP 或已有域名）
代理访问（可选）：Chrome 插件 -> 开发者受限代理 -> 127.0.0.1:项目原端口
页面对话：Chrome 插件 -> 本机受限桥接 -> Mac App 自动排队 -> 已有本地 ACP 会话
AI 答复与状态：Mac App -> 本机桥接 -> Chrome 插件 -> 继续追问 / 按需确认结果
```

本机桥接由 Mac App 管理，只提供局域网预览 / 反馈及 loopback 管理接口，不连接 Server。
App 通过已有本地会话能力执行插件反馈，不使用通用 AI API Key 或另建 AI 会话。
开启共享即允许绑定插件提交反馈后自动执行，不再逐条弹出反馈确认；
这不会改变 Chat 中 AI 工具审批或用户问题的既有处理逻辑。
这一实现是需求草案的本地试用版本，不是已完成的多用户产品。

已完成能力、验证记录及后续待办见 [开发进展](PROGRESS.md)。

## 在 Mac App 中使用

要求 Node.js 22+、运行中的 Mac App，
以及一个属于该前端项目、已启动且空闲的普通 ACP 会话（非 PTY、非外部 AI API 会话）。
首次试用请选择测试项目。目录授权与工具审批仍由 TermRelay 管理；
请检查目标会话的自动审批设置。

1. 在 App 中打开对应项目的 ACP 会话，点击顶部“共享预览与对话”。
2. “共享与配对”页显示固定绑定的会话和本地目录，不需要填写会话 UUID。
3. 输入完整项目访问地址，例如 `http://192.168.1.20:5173/project/` 或 `https://my-project.test:8080/`，选择访问方式：
   **直接访问（默认）**适合业务方已能访问的局域网 IP / 域名；**通过开发者电脑代理**适合需要转发到开发者本机服务的项目主机。
   再选择反馈服务使用的本机局域网 IP，点击“开启共享”。项目地址不接受账号、查询参数、hash 或 `localhost`。
4. 点击“显示插件目录”，供业务方安装；点击“复制插件配对配置”，把完整 JSON 发给授权验收者。
5. 在同一面板的“页面对话”页查看排队、运行状态与 AI 答复；结果未知时到 Chat 核实后手动处理。
6. 点击“停止共享”关闭对话服务与本次代理；直接访问的项目服务不受影响，不会取消已经开始的 AI 轮次。

App 自动从当前本地会话取会话与工作区绑定，自动管理后台进程。
当前一次只能共享一个项目；切换主窗口不会重绑，另一个项目需先停止原共享。
不需要运行终端命令、查 UUID、阅读凭据文件或打开单独的 Web 管理页。
高级设置允许修改共享 / 管理端口和选择 Node 可执行文件；
未找到 Node.js 22+ 时 App 明确报错，不自动下载安装。

App 无需连接 Server；使用公网配对连接 Server 或完全离线都不影响此功能。
验收者只需能通过受信局域网访问开发者 Mac，不需要 Server 登录身份或设备凭据。
Server 的远程终端 / 会话能力与本功能独立，不要为分享预览而开放 Server 或绕过公网认证。
默认共享服务为 `http://<开发者局域网IP>:18420`，本机内部管理端口为 `18421`。
配对配置包含反馈服务地址、验收与代理配对凭据，以及 `previewURL` / `accessMode`，不含管理 Token 或会话 ID；
整个 App 同时只允许一个插件实例连接，不是每个 Chat 各一个；
同一个 Chrome Profile 的多页面共用连接和反馈列表，本版没有独立用户权限模型。

App 数据保存在 `~/Library/Application Support/TermRelay/PreviewSharing/`，
按 `local/<会话 UUID>/` 隔离，并校验设备和工作区绑定。凭据及反馈仅留在本机，换会话不默默迁移旧反馈。
旧版本按 Relay 隔离的数据目录保留原样，不自动迁移；升级后首次开启会生成新的局域网配对，需重新导入插件。
正常退出 App、会话停止 / 关闭时停止共享；Server 地址改变或连接断开不停止共享。
后台服务监测所属 App 进程，父进程退出后自动关闭，不清理无关进程。
停止后再次开启同一绑定会恢复原配对与反馈，不等于撤销旧凭据。
Mac 发布脚本将 companion 和 extension 资源放进 App；Node 运行时仍需本机安装。

## 安装 Chrome 插件

插件安装在**验收者电脑**上。直接访问无需独立 Chrome Profile，也不修改 ZeroOmega 或 Chrome 代理。
仅使用内置代理时，推荐独立的 Chrome 用户配置（Profile）：点击 Chrome 右上角头像，
添加用户配置，不登录账号继续，命名为“项目验收”。不要在此配置中安装 ZeroOmega。
普通新窗口或新标签页不隔离代理设置；独立 Profile 中的内置代理不会修改日常 Profile 的 ZeroOmega 配置。
插件不能自动创建或确认专用 Profile，业务系统需在此 Profile 中单独登录一次。
以后从“项目验收”用户配置进入，复用已保存的插件和配对配置。

以下操作均在验收者电脑上完成；内置代理模式使用“项目验收”Profile：

1. 打开 `chrome://extensions`，开启开发者模式。
2. 选择“加载已解压的扩展程序”，选择本目录的 `extension/`。
3. 点击工具栏中的插件图标，在快捷弹窗点击“配置”。首次使用时，在配对输入框粘贴开发者从 App 复制并发来的完整配置，点击“保存并连接 App”。
   无需逐项填写地址或密钥；保存后会清空粘贴框，不在状态信息中展示凭据。
4. 直接访问点击“打开项目”，代理访问阅读范围并勾选确认后点击“打开预览”。
   首次访问新的 HTTPS 项目主机时，按 Chrome 提示授权站点访问以启用反馈；拒绝后可以重试。
   插件自动连接并打开配置中的完整地址，仅代理模式会开启代理；保存配置本身不会偷偷开启代理。
5. 进入项目的具体页面，入口可以包含项目路径，不再限定固定域名。
   页面右下角会出现对话图标；若配置稍晚才完成，可刷新项目页面。

可再次点击主按钮打开项目；入口链接保留在连接状态区。
新标签页打开失败时会明确提示，已建立的连接保持可用，可用入口链接重试。
切换开发者配置后关闭旧预览页面，代理模式须重新确认。停止验收时关闭快捷弹窗中的“共享连接”开关，或在设置页点击“关闭连接”。
开发者更换项目地址或访问方式后，须重新复制并导入配对配置；插件会拒绝使用过时配置。
旧版仅有服务地址和两项 Token 的配置仍兼容原域名代理，不会强制迁移 ZeroOmega 模式。

工具栏图标默认打开快捷弹窗，不再直接打开完整设置页。弹窗展示当前项目、访问方式和连接状态；
“共享连接”开关可以快速开启 / 关闭，另有“打开项目”和“配置”按钮。
打开弹窗会检查已有连接，但不会自动重连已关闭的连接。首次代理开启仍需明确确认；同配置后续可直接切换，改变配对或代理方式后重新确认。

设置页顶部突出当前项目、当前访问方式、项目与反馈服务地址，以及“连接中 / 已连接，未开启 / 已开启 / 已关闭 / 连接异常”等状态；不输出原始 JSON。
保存配置后收起配对输入，主操作集中在状态区下方；ZeroOmega、专用 Profile 引导、手动配置和单独暂停代理收在高级设置中，“重新连接”保留在主操作区。
既有 ZeroOmega 用户保留原模式与配置，不会被强制切回内置代理。
更换配置会断开旧环境并要求重新确认代理范围；关闭旧预览标签页，再重新打开。
更新已加载的插件后，到 `chrome://extensions` 点击重新加载，并刷新设置页和业务页面。
在 Chrome 工具栏的扩展菜单中固定「TermRelay」，即可看到蓝紫色对话气泡与青色点选光标图标。Chrome 扩展管理保留必需的技术名称，页面入口、面板和弹窗只展示图标；页面图标保留悬停提示与无障碍标签。
工具栏和扩展管理页共用 16 / 32 / 48 / 128px PNG；修改图标后运行 `pnpm --filter @termrelay/chrome-extension icons` 重新生成。

代理模式只匹配本次项目地址中的主机，并将原端口转发到开发者电脑的 `127.0.0.1:原端口`。
该主机的所有合法端口都转发，不使用端口允许列表；直接访问模式不开放预览代理。
例如页面在 `8080`、CSS / JS 在 `8101`，或 HMR 使用其他端口，都不需要额外填写。
持有代理凭据的人可通过此域名连接开发者电脑的全部本地 TCP 端口，而不只是当前项目服务；
只应在受信局域网内向可信验收者分享，不应将本服务暴露到公网。
代理访问不需要业务方修改 hosts；复用项目原 HTTP / HTTPS 服务，HTTPS / WSS 走 CONNECT，HTTP / WS 支持转发与连接升级。
其他主机或硬编码 localhost 不会被自动改写。直接访问只授权项目 origin（协议、主机、端口），
代理访问的反馈允许项目地址同协议、同主机的任意合法端口；入口路径不限制后续业务路由。

### 选择代理方式

仅代理访问项目需要以下设置；直接访问项目会隐藏这些选项，不触碰既有代理规则。

高级设置提供两种方式，选择会保存在当前 Chrome Profile 中；未选择过模式的安装默认使用内置代理。
切换方式会释放插件自己的代理设置并清除开启确认，但保持 App 连接，不自动接管 Chrome。

- **插件内置代理**：原有一键 PAC 能力，预览域名走开发者 Mac，其余域名 `DIRECT`，
  不合并公司代理。仅在获准且无需其他代理的独立 Profile 使用；
  管理员或其他扩展占用代理时拒绝启用，不抢占设置。
- **ZeroOmega 统一分流**：插件不写入 Chrome 代理配置，保留 ZeroOmega 的规则与默认情景；
  只维持 App 连接、自动响应当前预览代理的认证及处理反馈。
  设置页根据已保存的开发者地址生成可复制的配置步骤，不导出 Token，也不提供会覆盖原规则的整份备份。

ZeroOmega 快速配置：

1. 在插件选择“ZeroOmega 统一分流”，保存 App 配对配置，点击“复制配置方案”。
   即使首次连接失败，保存后仍能生成方案。
2. 在 ZeroOmega 新建名为“插件预览”的“代理服务器”情景：
   协议选 **HTTP**，服务器与端口按生成方案填写（即 Mac 服务地址的主机与端口，不是项目端口）。
   用户名、密码留空；插件用本次连接的动态凭据自动认证，不要填写配对密钥。
3. 在正在使用的“自动切换”情景顶部添加两条“主机名通配符”规则：
   开发者 Mac 的服务 IP / 主机名 → **直接连接**；
   本次项目地址中的主机（以插件生成的方案为准）→ **插件预览**（匹配全部端口）。
   保留其余规则与默认情景；不要将整个浏览器切到“插件预览”代理情景。
4. 应用 ZeroOmega 选项，并在其工具栏菜单选用上述自动切换情景。
   返回插件勾选确认，点击“使用 ZeroOmega 打开预览”，在新打开的页面中验证。
   “App 已连接”不代表 ZeroOmega 规则已验证，因此设置页显示“ZeroOmega · 待验证”，不假报预览成功。
5. 更换开发者 Mac 地址时，按重新生成的方案更新服务器、端口与直连规则，并按需移除旧规则。
   若切回内置模式，需先在 ZeroOmega 中释放代理控制，再确认开启插件。

ZeroOmega 模式下不提供误导性的“只暂停域名代理”按钮；关闭快捷开关或点击“关闭连接”会撤销本次认证、
关闭已有预览隧道并释放 App 独占连接，但**不会修改或删除 ZeroOmega 规则**，请按需自行停用新增规则。
内置模式的暂停只释放本扩展自己的设置，不恢复或覆盖其他人的代理配置。
浏览器的全局代理错误只在插件实际接管内置代理期间归属于插件，并在设置页显示；
ZeroOmega 或其他扩展控制代理时，不再将它们的全局错误重复标记为插件错误。
此模式不绕过管理员网络策略，也不自动解决证书、网络不可达或业务登录问题。

浏览器扩展请求 HTTP companion 的权限较宽（`http://*/*`），因为开发者 IP 可变；
反馈服务地址只允许配置私网 / loopback；项目地址单独按 HTTP(S) URL 校验。
新的 HTTPS 项目主机使用可选权限按需授权，反馈脚本按当前分享站点动态注册，后台和桥接再次校验页面范围。
不得在不可信局域网或公网部署反馈服务。

## 连接与状态同步

- 每个 Chrome Profile 保存独立插件实例 ID；第二个插件实例连接会收到“已连接另一个插件实例”，不能提交反馈或使用代理。
- 插件后台约每 30 秒续约，页面约每 3 秒更新连接与执行状态，App 约每 1 秒同步本机反馈服务。
- 内置模式高级设置中的“只暂停域名代理”只关闭域名代理；要让另一个插件接入，请关闭快捷开关或点击“关闭连接”。
  断开会释放独占连接、关闭已有代理隧道，并停止后台续约；打开的页面不会自动抢回连接。
- 浏览器异常退出后约 90 秒无续约释放连接；重新连接会签发新的连接与代理凭据。
  配对配置中的凭据用于建立连接，不能直接绕过独占连接限制使用代理。
- 断开插件不会取消已经提交或正在执行的反馈；重新连接后可继续查看状态。

## 围绕网页与 AI 对话

1. 正常操作业务页面，点击右下角的对话图标。
2. 可直接围绕当前页面提问，也可“选择元素”、扩大范围或框选截图；不强制选择元素。同一页面内选择元素或“当前页面”保留已附截图；跨页面时须先处理旧截图，避免发错图。
3. 输入“消息”，例如询问点击后的逻辑、解释页面状态，或明确提出修改请求。额外背景放在“补充上下文”。
4. 点击“发送给 AI”；Chat 忙时排队，工具审批与阻塞问题仍在 App Chat 内按原设置处理。
5. 面板上方按时间顺序显示“你 / AI”对话块，下方固定消息输入区。页面选区、补充背景与截图属于对应消息的附件，不是独立的修改任务表单。截图按需读取，可在消息中预览并放大；回复中的三反引号代码段单独显示为代码块，不执行 HTML，也不自动加载回复里的外部图片。
6. 发送成功后清空本条文字、选区和截图；收到回复后可直接输入下一条，也可点击历史答复下的“继续对话”。追问不会自动继承上一条的选区或图片，需要时重新添加。追问关联上一条消息，并携带最多 8 条祖先消息的有限文字上下文；历史请求不构成重新修改的授权。当前消息首次收到答复时滚动到结果；无变化的状态轮询不重建对话或打断阅读位置。
7. “新话题”清除追问关联和当前附件，但仍复用同一个绑定会话，不创建隔离会话。问答不要求验收；涉及修改时可自行刷新核实，并按需“确认结果”。

App 只回传关联轮次的公开答复，不回传思考过程、工具输出或原始本机错误详情。
单条回复最多显示 16000 个 UTF-16 单元，超长提示到 App 查看；目前以轮次答复为主，不提供逐 token 实时回显。
AI 答复可能包含项目代码或路径，同本共享连接中的消息一样对受信协作者可见。
旧记录的“效果满意 / 再调一调”继续兼容，不再作为新对话的必经步骤。

执行前先在本机持久化发送意图，再由 App 直接启动绑定的本地会话并持续回写执行状态。
命令或提交结果未知时不自动换编号重试。桥接重启将未确认发送标为 unknown，
必须到 TermRelay 核实。正在执行或存在未知结果时，不启动下一条；确定完成或失败后才继续队列。
若 App 与桥接间响应丢失，记录仍为“发送中”时也须核实本地轮次后人工结束，不能直接重发。
若已核实失败或未执行，开发者可在 App 明确结束为失败，不必假装修改成功交付验收。
队列复用最多 1000 条的本地反馈存储，按提交顺序逐条等待 Chat 空闲，不创建替代会话。

## 用截图提问或提出请求

需要同时更新 Mac App 及插件，并重新开启共享。Codex 使用 App Server 原生图片输入；
Copilot / DSH 仅在 ACP 握手宣告支持图片时启用。不支持图片或旧版 App 会禁用页面中的“框选截图”，文字反馈不受影响。
图片输入协议可用不代表所选模型一定支持视觉；Provider 拒绝时按原失败 / 未知结果流程处理，不自动重发。

1. 在已开启共享的项目页面点击工具栏中的扩展图标，选择“截图对话”。这次工具栏点击提供 Chrome 当前标签页临时截图授权，不申请所有网站截图权限。
2. 拖拽框选当前可见页面区域；取消按钮或 Esc 可退出，不截取整个桌面。也可在页面反馈面板点击“框选截图”；缺少授权时会提示从工具栏进入。
3. 预览图片，可放大查看、移除或重新框选。截图不会包含插件的面板或框选遮罩，但可能包含业务表单、账号和其他可见敏感内容，不自动打码。
4. 输入问题或请求，明确勾选图片确认后点击“发送给 AI”。截图与文字一起进入绑定会话，App Chat 显示图片；提问不会默认要求 AI 修改代码。
5. 已提交记录可点击“查看截图”。提交结果未知时锁定原内容，用原编号重试确认，不换编号重发。

截图预览标记“尚未上传，随消息发送”；仍在点击“发送给 AI”时上传，不新增独立上传步骤。
发送后插件必须收到对应图片尺寸的回执才确认附图成功，否则保留原编号并提示未确认。
App 的“页面对话”记录会实际读取并解码图片，显示“截图已接收”和可放大的实图；无附件时明确显示“本条消息未附图片”。
桥接与 App 派发均校验图片数量，不允许声明有图却静默降级成文字。接收、解码和向 Provider 发送是传输证据，不代表模型已经看懂图片。

每条反馈最多一张 PNG，最长边不超过 1600 像素、图片不超过 1 MB；过大的区域自动缩小后预览，仍超限则要求重新框选。
截图以反馈附件保存在开发者本机私有 JSON，编码后图片总量上限 32 MB；列表轮询不传整图，按需读取须通过配对和有效连接校验。
截图会作为图片输入发送给当前 AI Provider，可能离开局域网，保留与处理规则取决于该 Provider。
本轮不含箭头 / 画笔标注、多图、全页滚动截图或录屏；已有截图不会因页面刷新自动更新。

## 本版限制与边界

- 没有跨会话工作区锁，执行期间不要在其他会话或人工轮次并行修改同一项目。
  自动队列不是跨会话强制排他；核心工具仍对自身会话状态作最终裁决。
- 不支持手机扩展、单次分享配置多个主机、同 Profile 同域名按标签页分流；不同项目可分别配置自己的域名或局域网 IP。
- 仅支持顶层普通 DOM；iframe、Shadow DOM、Canvas 可选外层容器或整页反馈。
  页面先注册的事件处理器仍可能先执行，选取交互应先在测试页面确认，勿用于危险操作。
- 不自动采集原始 outerHTML、表单值、Cookie、存储或全量网络；DOM 摘要只发送有限文字与结构定位线索。
   用户主动添加的截图是可见像素，可能包含表单当前值等敏感信息，提交前必须检查并确认。
  URL 查询参数和 hash 本版全部丢弃，包括 hash 路由；必要复现条件需人工补充。
- 当前元素采集上限与字段可在 `companion/model.mjs` 查看，服务端再次验证并构造允许字段。
- 元素定位不是源码定位；没有可靠的历史元素重定位或自动页面操作。
- 浮层不改变业务布局，草稿仅保留在当前页面内存，刷新或关闭会丢失。
  提交未确认时锁定内容并使用原 UUID 重试确认，避免重复记录。
- 反馈列表按当前页面 origin（含端口）展示，不是严格逐路由过滤。
- 文字与截图记录保存在本机 JSON，最多 1000 条，并对截图总量设限；没有自动清理、云同步或多用户权限系统。
- LAN companion 使用明文 HTTP，代理凭据为 Basic，仅供获准的受信网络试用。
  它与页面原有的 HTTPS 是不同链路；正式部署需为控制及代理接入另行设计传输保护。
- 撤销试用凭据时先停止服务，归档旧数据并使用新的数据目录启动；无在线凭据轮换 UI。
  App 尚无重置配对的原生入口，单纯“停止 / 开启”不会轮换凭据。

## 开发诊断入口

`companion/main.mjs` 与 loopback Web 管理页保留用于自动化检查和底层诊断，
不是面向用户的主流程。单独运行需显式传入 `--session`、`--device`、`--workspace` 本地绑定，
使用本目录 `.local/` 或 `--data-dir`；诊断管理页不提供 AI 执行入口，反馈由 App 自动派发。
不要同时绑定 App 正在使用的数据目录或监听端口。

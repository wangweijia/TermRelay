# 聊天附件

Mac 的结构化聊天，以及连接到该 Mac 的 Web / 手机聊天，支持图片、PDF、TXT 和 Markdown 附件。
先更新 Server 和 Web，再运行新版 Mac 客户端。PTY 终端与外部 AI API 会话不接收聊天附件。
Linux 目前不公布附件能力；带附件的轮次会明确拒绝，不会忽略文件后只发送文字。

## 使用

- Mac：点击「添加图片 / 文件」、拖入文件，或在输入框粘贴图片 / 文件。附件可以与文字一起发送，也可以单独发送。
- Mac 输入框在中文等输入法组字期间保留候选文字与光标，不因后台状态同步覆盖；组字期间的回车交由输入法处理，完成选词后才响应发送快捷键。
- Web / 手机：点击「添加图片 / 文件」选择文件，桌面浏览器也支持粘贴图片与拖入文件。上传完成后才允许发送。
- 草稿显示图片缩略图，可以移除附件；Web 上传失败可以重试。消息只有在设备确认提交成功后才清空草稿。
- 消息记录显示附件名称与大小。Mac 显示本地图片缩略图；Web 点击图片附件加载原图，点击文档附件下载原文件。读取要求目标 Mac 在线。

支持 PNG、JPEG、WebP、PDF、UTF-8 TXT / Markdown；每条消息最多 8 个文件，单文件最多 20 MiB。
图片最多 4000 万像素、单边最多 20000 像素。每个会话最多约 256 个文件 / 200 MiB，本机附件总量最多 2 GiB。

## 智能体输入

- Codex：图片通过 App Server `localImage` 输入，随当前轮次提交；不依赖智能体先主动寻找文件。
- Copilot / DSH：读取 ACP v1 握手中的 `agentCapabilities.promptCapabilities.image`；声明支持时发送图片内容块，未声明时明确报错并保留草稿。实际视觉理解还取决于所选模型。
- 文本文件：附上 UTF-8 内容；长文件每份截取前 120000 个字符，并明确标注截断与设备本地完整文件路径。
- PDF：Mac 用 PDFKit 提取文字，最多处理前 200 页 / 120000 个字符，保留页码；加密 PDF 和没有可提取文字的扫描件会报错。扫描件请先 OCR，或把页面作为图片发送。
- 每轮提取文字总量不超过 240000 个字符，超过时要求减少附件。原文件保留，智能体能否通过工具继续读取仍受其沙箱约束。

本功能复用设备上已有的智能体登录与配置，不引入独立的模型 API 上传服务。

## 存储与传输

原文件副本位于 Mac 的 `~/Library/Application Support/TermRelay/Attachments/<session-id>/<attachment-id>/`。
原文件的移动或删除不影响副本；工作区绑定也只保存于 Mac。目录使用私有权限，不按用户提供的文件名构造磁盘路径。

Web 使用 `/api/sessions/:id/attachments` 查询能力与传输文件。每个分块最多 192 KiB，Server 沿现有设备 WebSocket 中转，
Mac 校验会话 / 工作区后保存、确认。重复分块必须与已保存的内容一致，支持安全重传；未完成的文件不能提交给智能体。
Server 以连接、设备、会话和请求 ID 匹配响应，限制并发与等待时间；上传者不能指定设备本地路径。

聊天命令只包含附件 ID，`user.message` 历史只包含 ID、名称、MIME 类型和大小；不保存文件二进制或 Base64。
附件传输使用独立请求 / 响应，不进入有序事件 journal，也不随重连历史重放。

未发送附件在再次添加文件触发清理时回收超过一天的草稿；发送中的附件受保护，已发送附件跟随历史保留。
删除历史时，Mac 本地删除会清理副本；Web 删除会向在线设备发送清理请求。
设备离线、清理失败或删除时 Server 重启的情况下，远端删除不能保证清理本机副本；可以在本机附件目录按会话清理。
关闭聊天窗口保留已发送附件，避免破坏服务器历史中的附件引用。

## 验证

合成测试覆盖分块顺序、重复分块、会话隔离、未完成文件、无效格式、PDF 提取、附件消息历史、
Codex 图片 / 文档映射、ACP 图片能力与响应关联。普通测试不启动真实智能体或发送模型请求。
实际 CLI / 模型组合以及文件选择、粘贴、拖入的最终交互仍需要实机验收。

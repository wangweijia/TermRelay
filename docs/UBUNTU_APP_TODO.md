## 1. 目标与边界

目标是在 Ubuntu / Xubuntu 上提供独立于 macOS App 的无界面 TermRelay Agent，
以 CLI 作为部署管理入口、后台服务作为执行入口，复用同一套 Server、Web 和 JSON Schema 协议。
Linux 自己拥有本地目录、凭据和子进程，不经过 Mac 转发，也不依赖 Mac 在线。

**已确认方向**：Linux 与现有 App 的连接、鉴权、路由、持久化和交互语义保持一致，
只是不提供本地 App UI。聊天、模型设置、审批、用户问答和结果查看仍通过现有 Web / 手机完成，
不另建 Linux 专用交互协议，不把“无 UI”解释为删除交互或默认自动审批。

当前工作区已迁移为 TypeScript CLI、headless 服务和 Codex App Server 适配器，
直接使用现有生成协议类型 / Schema。systemd / `.deb` 发布包按架构内置私有 Node，
目标机器不需要预装 Node 或 Python；旧 Python / GTK / VTE 实现已移除。
新增能力仍需目标系统实机验收，不能等同于全部交付完成。
目标系统为 Ubuntu / Xubuntu 22.04、24.04；当前不交付本地桌面入口。
GNOME / Xfce / X11 / Wayland 的图形验收仅适用于未来重新开发可选桌面 UI 的情况。

**远程创建会话是 macOS / Linux 的通用能力，不是 Linux 特例**，按 U-024 统一设计和验收；
macOS 保留本地 UI，但也应支持从同一个 Web 入口远程创建会话。

实施时必须保持以下边界：

- PTY 只交换终端字节和 input / resize / interrupt；ACP 只交换结构化动作、事件、审批和问答。
- Codex App Server、Copilot ACP、DSH ACP 的协议解析在 Linux Adapter 内完成，不移到 Server / Web。
- Linux 保存真实路径、脚本和代理地址；Server / Web 只持有必要的不透明 ID 与展示元数据。
- 两端沿用设备主动出站连接 Server 的拓扑；不直接暴露 Provider 原始 ACP / JSON-RPC 公网端口。
- 跨端协议先修改 `packages/contracts/**/*.schema.json`，通过生成器更新产物，不手改 generated 文件。
- 只公布实际可用能力；不支持、未安装、未登录、权限不足或版本不兼容时明确报错。
- 新增数据库结构使用显式 TypeORM migration，继续保持 `synchronize: false`。
- 普通自动化测试使用假 Agent；真实 CLI 探针需显式开启，模型请求需要单独授权。

## 2. 当前基线：哪些已经存在

以下为代码已有能力，**不等同于 Ubuntu / Xubuntu 实机验收完成**，后续开发不应重复当成从零实现。

| 能力 | 当前情况 | 仍有边界 |
| --- | --- | --- |
| 无界面入口 | `src/cli.ts` / `service.ts`，已移除 Python / GTK | 没有本地窗口；旧 GUI 配置不自动导入 |
| 真实 PTY | node-pty、登录 Shell、resize、Ctrl-C、停止 | 本地通过 CLI 登记授权目录与启动配置，Web 提供终端 UI |
| 设备协议 | `platform: linux`，注册、心跳、现有 Server / Web 路由 | headless 只公布启动成功的 shell / codex；远程创建仍关闭 |
| 远程交互 | PTY 命令、Codex 结构化事件 / 配置 / 审批 / 问答、accepted / 最终 ACK | Copilot / DSH ACP、AI API / 快捷任务未实现，真实闭环待验收 |
| 公网配对 | 终端网址 / 用户码、TLS 和 Authorization Header | CLI 支持显式选择 0600 明文凭据文件；没有加密钥匙环 |
| 断线补传 | 运行期间的序号、watermark、未确认输出重传 | journal 不落盘，App 重启不能补传 |
| 输出约束 | 未确认输出合计 16 MiB，网络 / RPC / PTY 有界缓冲 | 达到上限明确报错，不伪造完整历史 |
| 进程归属清理 | 独立 supervisor、Linux subreaper、后代进程清理 | Linux 特有行为仍需目标系统验证 |
| 打包与自动化入口 | 内置 Node / 生产依赖的按架构 `.deb`、systemd 用户 unit、Ubuntu headless CI | 发布目录在开发主机检查；尚无实际 Linux 安装、systemd / linger 验收记录 |
| 本地配置 | 持久设备 / 工作区 / 启动配置 ID、Codex 路径、0600 原子写入、运行锁 | 执行会话、journal 和命令去重状态仍仅在内存 |

当前固定限制：headless 最多 8 个启动会话、128 个授权工作区；
同一进程不能切换到其他 Server；退出会停止本地进程且不保留未同步输出。

## 10. 建议交付顺序

| 阶段 | 任务 | 可对外声明的范围 |
| --- | --- | --- |
| L0：无界面运行基础 | U-023、U-001～U-004、U-006～U-008 必要部分 | 可通过 SSH 部署的服务，无 GUI 依赖；尚不宣称 ACP 可用 |
| L1：通用远程 ACP 闭环 | U-024、U-010、首个 Provider、U-015 | 同一个 Web 入口可在 Mac / Linux 创建并操作已验收的 ACP 会话 |
| L2：可靠性与能力补齐 | U-005、U-006～U-008 剩余项、其余 Provider、U-016～U-017 | 持久化、历史、预览和多 Provider 能力按项交付 |
| L3：扩展执行服务 | U-018～U-020 | 已验收的快捷任务与第三方 AI API 能力 |
| 持续维护 | U-021～U-022 | 平台文案、版本兼容、发布与测试证据持续同步 |

U-009 / U-014 是可选 GUI 工作，不参与 headless 主线的关键依赖。
U-018 在工作区、配置与进程基础就绪后可独立推进，不必等待全部 ACP Provider。
U-019 不能因 Adapter 已能启动就跳过执行隔离与权限验收。
依赖只按各任务显式记录计算，不把表格先后顺序当成强制依赖。

## 11. 非本轮功能差距 / 需另行决策

以下不是“macOS 已经具备而 Linux 遗漏”的现成功能，不混入必补清单：

- Skill 管理仍有单独的跨 Provider 方案，见 [Skill 管理 TODO](SKILL_MANAGEMENT_TODO.md)；
  Linux 应在通用方案落地后接入，不能把该方案写成当前 Mac 已支持。
- AppImage、Snap、Flatpak、自动更新和 APT 仓库分发需单独决策，首版 `.deb` 不依赖这些渠道。
- 托盘、窗口关闭后驻后台和进程跨服务重启托管需单独决策；
  systemd 常驻运行已纳入 U-023，但服务真正停止时仍应清理所属进程。
- 远程新建已确定为两平台共用能力，见 U-024，不再列为待决定是否支持。
  多 Server 同时连接仍需单独的授权与身份隔离设计。
- 新增 Claude / Gemini 等 Provider 属于后续扩展，不是本次对齐现有三种 Agent 的前置条件。

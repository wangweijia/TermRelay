## 1. 目标与边界

目标是在 Ubuntu / Xubuntu 上提供独立于 macOS App 的 TermRelay 桌面应用，
分阶段补齐现有 macOS 端的主要能力；复用同一套 Server、Web 和 JSON Schema 协议。
Linux 自己拥有本地目录、凭据和子进程，不经过 Mac 转发，也不依赖 Mac 在线。

当前技术路线为系统 Python 3.10+、GTK 3、VTE 和 `.deb`，
目标系统为 Ubuntu / Xubuntu 22.04、24.04。GNOME、Xfce、X11、Wayland 的适用组合需分别验收，
不能把“在 Xvfb 下启动成功”视为所有桌面环境均兼容。

实施时必须保持以下边界：

- PTY 只交换终端字节和 input / resize / interrupt；ACP 只交换结构化动作、事件、审批和问答。
- Codex App Server、Copilot ACP、DSH ACP 的协议解析在 Linux Adapter 内完成，不移到 Server / Web。
- Linux 保存真实路径、脚本和代理地址；Server / Web 只持有必要的不透明 ID 与展示元数据。
- 跨端协议先修改 `packages/contracts/**/*.schema.json`，通过生成器更新产物，不手改 generated 文件。
- 只公布实际可用能力；不支持、未安装、未登录、权限不足或版本不兼容时明确报错。
- 新增数据库结构使用显式 TypeORM migration，继续保持 `synchronize: false`。
- 普通自动化测试使用假 Agent；真实 CLI 探针需显式开启，模型请求需要单独授权。

## 2. 当前基线：哪些已经存在

以下为代码已有能力，**不等同于 Ubuntu / Xubuntu 实机验收完成**，后续开发不应重复当成从零实现。

| 能力 | 当前情况 | 仍有边界 |
| --- | --- | --- |
| 独立 Linux 桌面入口 | `apps/linux/termrelay/app.py`，GTK 3 + VTE | 目前是终端标签页，不是完整会话工作台 |
| 本地真实 PTY | 登录 Shell、选目录、多标签、复制粘贴、resize、Ctrl-C、停止 | 没有 Provider 选择和专用 Agent 启动配置 |
| 设备协议 | `platform: linux`，注册、心跳、现有 Server / Web 路由 | `tools` 当前只公布 `shell` |
| 远程 PTY 交互 | input / resize / interrupt / stop、命令 ACK、内存去重 | 没有 ACP / AI API / 快捷任务命令处理 |
| 公网配对 | 浏览器授权、凭据输入、TLS 和 Authorization Header | 凭据只在内存中，不支持钥匙环记住授权 |
| 断线补传 | 运行期间的序号、watermark、未确认输出重传 | journal 不落盘，App 重启不能补传 |
| 输出约束 | 未确认输出合计 16 MiB，VTE 回滚 10000 行 | 达到未确认输出上限会报错并停止产生日志的会话 |
| 进程归属清理 | 独立 supervisor、Linux subreaper、后代进程清理 | Linux 特有行为仍需目标系统验证 |
| 打包与自动化入口 | `.deb` 脚本、desktop 文件、Ubuntu 22.04 / 24.04 CI 定义 | 缺少本文登记的真实桌面验收和发布记录 |
| 本地配置 | 保存设备 UUID 和最近 Server URL，配置文件权限 `0600` | 工作区 ID、会话信息和命令去重状态仅在内存 |

当前固定限制：最多同时运行 8 个会话、每次打开 App 最多创建 128 个会话；
同一进程不能切换到其他 Server；退出会停止本地进程且不保留未同步输出。

## 10. 建议交付顺序

| 阶段 | 任务 | 可对外声明的范围 |
| --- | --- | --- |
| L0：PTY 首版验收 | U-001～U-004、U-002 的实际发布产物 | Ubuntu / Xubuntu 的独立 PTY 客户端，不宣称 ACP 可用 |
| L1：稳定日常使用 | U-005～U-009 | 工作区 / 会话管理、凭据与离线能力完善，限制明确 |
| L2：结构化 Agent | U-010～U-017，Provider 可逐个交付 | 仅对已验收的 Provider 宣称 ACP、审批、历史和预览能力 |
| L3：扩展执行服务 | U-018～U-020 | 已验收的快捷任务与第三方 AI API 能力 |
| 持续维护 | U-021～U-022 | 平台文案、版本兼容、发布与测试证据持续同步 |

U-018 可在 L1 完成后独立推进，不必等待全部 ACP Provider。
U-019 不能因 Adapter 已能启动就跳过执行隔离与权限验收。
依赖只按各任务显式记录计算，不把表格先后顺序当成强制依赖。

## 11. 非本轮功能差距 / 需另行决策

以下不是“macOS 已经具备而 Linux 遗漏”的现成功能，不混入必补清单：

- Skill 管理仍有单独的跨 Provider 方案，见 [Skill 管理 TODO](SKILL_MANAGEMENT_TODO.md)；
  Linux 应在通用方案落地后接入，不能把该方案写成当前 Mac 已支持。
- AppImage、Snap、Flatpak、自动更新和 APT 仓库分发需单独决策，首版 `.deb` 不依赖这些渠道。
- 窗口关闭后驻后台、开机自启动、托盘和进程跨 App 重启托管尚需产品决策；
  当前“退出清理自己的进程”是明确行为，不应直接取消。
- 远程新建会话和多 Server 同时连接需要额外授权与身份隔离设计，不作为移除当前限制的快捷修改。
- 新增 Claude / Gemini 等 Provider 属于后续扩展，不是本次对齐现有三种 Agent 的前置条件。

# Chrome 本地预览与 AI 反馈需求草案

> 状态：需求讨论稿，已有独立实验实现；不表示下述草案能力均已实现。
> 日期：2026-10-28。
> 本文区分已确认范围、建议方案和待决策项，不将建议视为最终产品决定。
>
> 独立实验实现已放在 [`apps/chrome-extension`](../apps/chrome-extension/README.md)：
> 使用 App 托管的本机受限桥接作为现有 Server 浏览器协议客户端，
> 在 Mac 原生会话面板中开启共享、复制配对及人工确认反馈，不直接调用 CLI 或通用 AI API。
> 这不是所有草案项的交付：本版共享预览凭据、手动核实 AI 完成，不含多用户、
> 自动队列、跨会话工作区锁及可靠的历史元素重定位。第 5 节的独立 Server 反馈接口仍未实现。

## 1. 目标与场景

开发者在本机维护前端代码、运行 HTTPS 测试环境，并已在 TermRelay 中打开对应项目的 AI 会话。
业务方通过桌面 Chrome 访问该环境，主动操作和验收页面，在页面上提出改进意见。
反馈携带必要的页面上下文，经开发者确认后交给 AI 修改本地代码，再由业务方验收。

目标闭环：

```text
访问本地预览 -> 操作页面 -> 选取元素并提交反馈
    -> 开发者确认 -> 项目 AI 会话修改代码 -> 页面更新 -> 业务方验收
```

预览访问与反馈通信是两条独立链路；其中一条成功不代表另一条可用。

## 2. 已确认范围与前提

| 项目 | 当前结论 |
| --- | --- |
| 浏览器 | 优先采用桌面 Chrome 插件，不自研浏览器 |
| 页面域名 | 仅考虑 `page-gateway-local.nioint.com`，暂不设计每人不同域名 |
| 现有本机解析 | 开发者 hosts 将该域名指向 `127.0.0.1`，无需修改 |
| 页面 URL | 保留原 HTTPS 域名、端口、路径和查询参数；提交反馈时另做敏感参数过滤 |
| 多端口 | 项目本身使用多个端口；连接应按请求端口转发，不限定为 `8080` |
| HTTPS | 项目已提供 HTTPS；不额外提供页面 HTTPS 服务，不解密或替换 TLS |
| 证书与插件 | 暂按业务方证书信任、插件安装及代理配置权限均不是阻碍处理 |
| 网络 | 业务方必须可访问开发者代理端口；插件不负责穿透网络隔离 |
| 登录 | 业务方使用自己的账号，不复制开发者 Cookie、Token 或浏览器登录状态 |
| 页面操作 | 以业务方主动操作为主，自动化浏览器操作不是首版重点 |
| 截图 | 本期不设计截图采集、标注、上传或 AI 看图；只考虑文字及元素上下文 |
| AI 集成 | 希望复用 TermRelay，但通信接口、会话策略及授权模型尚未定案 |
| App 入口 | 必须直接在 Mac App UI 开启与管理，不要求用户运行 CLI、查会话 UUID 或打开独立管理页 |

首轮页面访问验证使用现有地址：

```text
https://page-gateway-local.nioint.com:8080/debug/foresight/foresight/foresight/market-tracker/nev2
```

## 3. Chrome 插件预览能力

### 3.1 建议连接方式

普通 Chrome 扩展不能直接提供等同于 hosts 的任意域名到 IP 解析覆盖。
建议使用 `chrome.proxy` 配置按域名选择代理，由开发者电脑上的受限 CONNECT 代理完成连接。

```text
业务方 Chrome：访问 https://page-gateway-local.nioint.com:端口/路径
    -> 插件选用 开发者局域网 IP:代理端口
    -> 代理校验访问权限、目标域名及授权端口
    -> 连接开发者电脑的 127.0.0.1:原请求端口
    -> 透传 TLS 到项目已有的 HTTPS 服务
```

代理端口与项目端口是不同概念。一个代理入口可服务多个授权项目端口，
不需要为每个项目启动额外的 HTTPS 服务。业务方不需要修改 hosts。
插件不应将页面 URL 重定向为 IP，也不应通过修改 Host 或忽略证书错误模拟域名解析。

### 3.2 功能要求

- 配置或配对开发者环境，显示环境名称、目标设备及连接状态；具体配置下发方式待定。
- 仅代理指定域名；其他流量保留经确认的既有网络路径，不直接覆盖企业代理规则。
- 多端口按原端口转发，但本机只允许开发者显式授权的端口，不开放任意本地服务。
- 原页面地址、登录语义和 HTTPS 保持不变；支持项目实际需要的 WebSocket / HMR。
- 禁用插件或退出预览模式后释放自己的代理设置，不覆盖其他扩展或管理员随后作出的配置。
- 同一 Chrome Profile 暂按同域名一次指向一个开发者环境设计。
  切换时应提示并处理相关标签页及既有连接，不能只修改 PAC 后宣称切换完成。
- 明确提示网络不可达、代理鉴权失败、端口未授权、目标服务未启动等错误；
  证书问题由 Chrome 正常报告，不静默绕过。

现有证书受信任仍需以证书域名匹配为前提。页面接口、静态资源、登录跳转和热更新
若指向其他本地域名、IP 或 `localhost`，需单独梳理，不能默认被此规则覆盖。

### 3.3 Mac App 入口与管理交互

用户主流程必须是 App UI，而不是命令行包装说明。当前已接入的实验界面为：

```text
项目 ACP 会话顶部
[共享预览与反馈]
         |
         v
+----------------------------------------------------+
| 共享预览与反馈                              [完成]  |
| 当前项目名称 / 目录                                 |
| 反馈固定送到此会话，不随主窗口选择切换                |
| [共享与配对]             [页面反馈 · 待处理数量]     |
+----------------------------------------------------+
```

“共享与配对”页按三个步骤组织：

1. 当前项目：展示现有会话与目录，不让用户手填 UUID，不根据域名猜会话。
2. 开放本机预览：填写项目端口、选择本机局域网地址、点击“开启共享”。
   自动取 App 当前 Server 连接，自动启动后台桥接；Node 路径和服务端口放在高级设置。
3. 发给业务方：显示插件目录、复制仅供验收者使用的配对 JSON、展示预览根地址。
   插件设置支持一次粘贴导入，不要求逐项复制 Token。

“页面反馈”页展示每条反馈的描述、页面、元素摘要与状态：

- 待处理时，点击“确认交给此会话修改”后再次确认目标与并发修改风险。
- 会话忙碌、已有未核实执行或共享已停止时不允许发送。
- 送达后回到会话查看审批和结果；核实执行结束并填写摘要后，交业务方验收。
- 结果未知时只能先核实，不提供直接重跑；确认失败或未执行可明确结束为失败。

共享面板固定绑定打开它的会话，一次只共享一个项目；新项目需先停止原共享。
停止共享不取消已发送的 AI 轮次，停止前明确提示。
会话结束、Server 连接断开 / 地址变更、App 退出时停止所属共享服务，
不能留一个仍指向失效项目的代理。底层 Node helper 是 App 管理的实现细节，
不是用户需要另行操作的 CLI 工具。

## 4. 页面反馈能力与交互草案

本节细化建议交互，供后续确认；尚无对应界面实现。
本期只做文字和元素上下文，不出现截图按钮，不要求录屏或浏览器自动操作。

### 4.1 入口与页面表现

插件只在已启用、已授权的预览环境页面注入反馈界面，不在登录页或无关网站显示。
页面默认保持正常操作，右下角显示一个可收起的悬浮按钮“反馈”，不自动进入元素选择模式。
点击后展开右侧浮层面板；面板覆盖页面但不压缩业务页面宽度，避免触发响应式布局变化。
面板和按钮使用隔离样式，不能修改业务页面的 DOM 内容、表单值或业务状态。
浮层可关闭；可从浏览器扩展图标重新打开。尺寸、颜色和具体视觉样式后续确定。

建议面板结构：

```text
原业务页面（可正常操作）           右侧反馈面板
                                +----------------------------+
                                | 页面反馈                关闭 |
                                | 项目 / 开发者 / 连接状态     |
                                | [新建反馈] [我的反馈]        |
                                |                            |
                                | [选择页面元素]              |
                                | 或 [反馈整个页面]           |
                                |                            |
                                | 选中对象 / 当前页面摘要      |
                                | 希望怎么改 *                |
                                | [多行输入框]                |
                                | 复现步骤（可选）             |
                                | [多行输入框]                |
                                | [查看随反馈提交的上下文]      |
                                |                            |
                                | [取消]          [提交反馈]   |
                                +----------------------------+
```

选择元素和整页反馈二选一；整页反馈用于流程问题、缺少内容或无法定位到具体元素的问题。
标题可由元素摘要和描述生成，不要求业务方额外填写标题、CSS selector、组件名或会话 ID。

### 4.2 如何选中元素

1. 用户先正常操作页面，到达要反馈的状态，例如打开弹窗或展开菜单，再点击“选择页面元素”。
2. 进入选择模式时收起编辑面板，保留顶部提示条：
   “移动鼠标定位，点击选中；Esc 退出”。仅此模式拦截用于选择的页面点击。
3. 鼠标移动时，用不参与页面布局的高亮框标记候选元素，
   显示简短标签，例如“按钮 · 查询”或“区域 · 市场趋势”。
4. 点击后锁定一个对象，退出选择模式并展开表单，显示元素摘要和高亮。
   选取用的点击不能同时触发页面跳转、提交表单、勾选或执行其他业务操作。
5. 优先将图标、文字等子节点归到最近的语义交互元素，例如点击按钮文字时选择整个按钮。
   表单显示可识别的祖先层级，允许点击“选择外层”切换到卡片、表格或容器，
   也允许“重新选择”；不依靠用户理解 DOM 层级。
6. 一条反馈首版只关联一个元素或一个页面，不做多个元素同时圈选。
   按 Esc 取消本次选择，保留已有描述和原选中对象；表单内另设“移除元素”切换为整页反馈。

高亮层自身不截获普通浏览模式的页面操作，插件面板、按钮、提示条不进入可选元素。
滚动或调整窗口时高亮跟随目标，不使用固定的旧坐标；离开视口时不自动强行滚回。
选择模式须在代表性业务页面验证点击拦截，不能假定能安全阻止所有页面自定义事件。
不确定能否安全选取的交互区域，应明确提示改用整页反馈，不冒险触发业务操作。

### 4.3 选择范围与动态页面边界

- 首版至少支持顶层文档中的普通 DOM 元素；iframe、Shadow DOM、Canvas 等不承诺内部选取。
  iframe 或图表可选择外层容器并补充描述，不伪造内部元素上下文。
- 鼠标悬停才出现、容易消失的菜单首版不承诺冻结；无法保持时可选触发元素或整页反馈。
- 高亮不是持久业务标记；关闭插件界面后移除高亮，不在原页面永久插入批注。
- 业务路由变化后不将未提交草稿自动绑定到新页面。
  草稿保留原路由并提示“页面已变化”，由用户继续提交原页面反馈或明确重新采集。
- HMR、刷新或重新渲染使目标节点失效时，保留已采集摘要，
  提示“原元素已变化，可重新选择”；不能静默改指向另一个相似节点。
- 默认使用清理后的路径及查询信息区分页面；hash 路由应保留路由语义。
  端口属于环境定位信息，不能忽略；筛选参数和敏感参数的规则另行定义。

### 4.4 怎么填写与提交

锁定对象后，面板至少显示“当前对象”“希望怎么改”“复现步骤”和“提交上下文”四个区域。
“希望怎么改”为必填，接受自然语言，例如：
“查询按钮不明显，希望改成主色并和右侧输入框对齐”。
复现步骤可选，不强迫业务方拆成多个技术字段。
已选元素摘要例如“按钮：查询”；整页反馈明确显示“整个页面”，避免误以为已关联某个元素。

用户展开“提交上下文”可查看将上传的经过过滤的 URL、元素文本、标签、定位线索及 DOM 摘要，
并可移除元素上下文，改为仅提交页面与文字。该入口不是展示未经处理的完整页面源码。
若内容超过限制，提交前提示被裁剪的部分；不隐藏裁剪事实。

提交时要求：

- 描述为空或目标环境未授权时禁用提交，并给出具体原因。
- 点击后显示“正在提交”，阻止重复点击；只提交反馈，不直接触发 AI 修改。
- Server 确认保存后显示反馈编号和“已提交，待开发者处理”，提供“查看反馈”“继续反馈”。
- 未发送成功时保留草稿，显示失败原因并允许重试。
  已发送但响应丢失时显示“提交结果待确认”，先按同一提交标识查询，不生成新反馈重发。
- Server 不可达时允许继续编辑，并明确“未提交”，不以成功提示代替本地暂存。
- 取消有内容的草稿前要求确认；收起面板不丢弃草稿。
  首版至少保证同一页面内的草稿保留，刷新、关闭标签页后的草稿恢复能力待确认。

### 4.5 提交后怎么看、怎么继续反馈

“我的反馈”仅展示当前用户有权查看的反馈，默认按当前预览及页面筛选。
列表至少显示反馈编号、描述摘要、元素摘要、提交时间和处理状态。
业务方可切换查看该预览下其他页面的反馈，不混入其他开发者环境的数据。
身份识别与“我的”权限模型仍待确认，不能仅依靠前端过滤实现访问限制。

点击记录显示原始反馈、补充描述、筛选后的处理结果与状态时间线；
不展示完整 AI 会话、终端、提示词或本机路径。
“定位原元素”只在当前环境和页面匹配且定位足够可靠时提供，点击后滚动并短暂高亮。
目标不存在或匹配不唯一时显示“元素已变化，无法可靠定位”，不自动选取第一个匹配项。

建议状态文案：

| 状态 | 业务方看到的含义与操作 |
| --- | --- |
| 待处理 | 开发者尚未确认执行；可以补充说明 |
| 等待执行 | 已确认，正在等待项目会话空闲 |
| 修改中 | AI 正在处理；可以补充说明，但不会把新内容自动插入当前轮次 |
| 待验收 | 显示修改摘要，提供“刷新页面”“验收通过”“仍需修改” |
| 已验收 | 业务方确认通过，保留记录 |
| 需继续修改 | “仍需修改”必须填写补充意见，关联原反馈并等待再次确认执行 |
| 执行失败 | 显示可公开的失败原因，由开发者决定后续处理 |
| 结果未知 | 提示等待开发者核实，不提供会导致重复执行的一键重跑 |

补充说明作为独立记录保存；反馈确认执行时固定本次输入版本，
执行中新增说明留待下一次处理。AI 轮次结束不等于业务验收通过。
“刷新页面”需要用户主动点击，有未保存的业务输入时不自动刷新。

### 4.6 采集与隐私边界

| 类别 | 内容与限制 |
| --- | --- |
| 反馈 | 修改描述、可选复现步骤、后续补充说明 |
| 页面 | 经过过滤的 URL、路由、时间、视口尺寸、可用时的预览版本 |
| 元素 | 标签、语义角色、有限可见文本、定位线索、位置及裁剪后的附近 DOM |
| 关联 | 预览标识、反馈 ID；设备、工作区与会话归属由可信绑定决定 |

元素信息应从允许的字段构造，不直接上传原始 `outerHTML`。
排除密码及其他表单当前值、隐藏字段、事件处理器、脚本、敏感属性和带凭据的链接参数；
可见业务文本仍可能敏感，需允许提交前检查并移除上下文。
Cookie、Authorization、浏览器存储和全量网络日志不采集，不进行截图采集。
具体字段允许列表和长度上限需在实现前定义，采集、上传及 AI 输入侧均需有界。

DOM 和业务描述属于不可信输入，不得作为扩大执行权限的依据。
元素定位不等于源码定位；组件标识、Source Map 或开发环境辅助接入属于后续可选能力。

### 4.7 本节交互验收要点

- 正常浏览时按钮、输入、滚动和路由不受影响；进入选择模式才启用选择拦截。
- 选择“查询”按钮不会实际执行查询，元素摘要对应整个按钮而非内部图标。
- 可以改选外层区域、重新选取、取消选取，以及不选元素直接提交整页反馈。
- 选中元素后滚动、路由切换和 HMR 不会静默改变反馈对象。
- 必填校验、提交中、失败保留草稿、未知提交结果查询均有明确界面表现。
- 成功记录可查看和补充；待验收后可以通过或填写继续修改意见，不自动刷新或标记通过。
- 不支持的页面结构有明确降级提示；不采集截图、凭据或未经筛选的完整 DOM。

## 5. 与 TermRelay 通信

### 5.1 建议边界

建议复用现有“浏览器 -> Server -> Mac”的控制边界，
新增受限的反馈接口，而不是让插件直接控制本地 CLI 或访问所有会话。

```text
页面访问：插件 -> 本机 CONNECT 代理 -> 本地 HTTPS 项目

反馈提交：插件扩展上下文 -> TermRelay Server 的受限反馈入口
    -> 保存反馈、校验预览权限与绑定
    -> 开发者确认
    -> Server 经现有设备连接转发
    -> Mac 校验本地授权并执行 AI 轮次
    -> Server 汇总受限进度供插件查询
```

反馈 API、查询方式（轮询或订阅）、扩展权限、鉴权与持久化结构尚未定义，
本文不声明任何新端点已经可用。须验证插件到 Server 的实际网络路径、
Chrome 权限与跨域限制，不能由业务页面任意调用本机服务。

插件只持有可撤销的预览 / 反馈范围凭据，不下发通用 AI API Key、
设备连接凭据或管理权限。是否允许提交者查看其他人的反馈另行确认。
实际工作目录、代理转发配置及执行权限由 Mac 所有者授权；
Server 保存不透明工作区标识，不保存真实本地工作目录。

CONNECT 代理属于本机网络组件，不属于 Server 的任意目标转发功能。
它与插件的部署、配对、访问鉴权和启停生命周期需单独设计。
如果代理运行在 Docker 中，容器的 `127.0.0.1` 不是宿主机，
必须显式处理宿主机目标，不能直接沿用原生本机转发配置。

### 5.2 当前实现可复用的部分与缺口

| 当前能力 | 对本需求的意义 |
| --- | --- |
| 普通 ACP 会话支持 `tool.turn.start` | 可作为绑定已有会话后的轮次执行基础，不等于已有受限反馈接口 |
| `tool.turn.start` 当前只接受 `text` | 可用于本期文字及裁剪后 DOM 的输入，具体编排与长度预算待定 |
| AI API 创建独立 conversation | 不能直接接管任意已有普通会话；不能靠传入普通会话 ID 复用 |
| 外部 AI API 支持 Codex / DSH | 不代表能用该 API 调用现有 Copilot 会话；DSH 不开放工作目录工具 |
| 外部 AI 会话使用自动审批 | 不应默认继承到业务反馈修改代码场景 |
| 通用 AI Key 权限不按预览隔离 | 不能直接分发给验收者或嵌入插件 |
| AI API 当前仅允许受信 LAN 调用 | 不因有预览代理就自动获得调用权限；不移除来源限制来适配插件 |

本期不设计截图或图片输入，不为此引入附件存储及多模态协议。

## 6. 会话策略：已有会话还是专用会话

会话策略是待决策项。两种方式应共用反馈记录与授权边界，不让插件直接决定执行目录。

| 方案 | 优点 | 代价与边界 |
| --- | --- | --- |
| 显式绑定已有项目 ACP 会话 | 保留开发上下文，符合当前已打开项目会话的场景；便于开发者接手 | 与人工输入争用，需要统一执行仲裁；会话结束后需重新绑定 |
| 为项目 / 预览创建专用反馈会话 | 反馈上下文独立，人工开发对话不被打断 | 不继承已有上下文；仍可能修改同一工作目录；需要新的创建与生命周期规则 |
| 每条反馈新建会话 | 单条上下文隔离 | 启动成本高、上下文重复，易并发改写同一目录，不建议作为首版默认 |

**讨论建议：首版优先由开发者显式绑定一个已有 ACP 会话，并逐条确认后执行。**
这不是最终决策。若实际使用更重视反馈隔离，可改为每个项目 / 预览一个持久专用会话，
但不应每条反馈自动启动新会话，也不应未经确认在两种策略之间回退。

无论采用哪一种方式，都需满足：

- 绑定包含明确的设备、工作区、会话及绑定版本，不能按“当前选中的窗口”隐式路由。
- 只使用支持项目文件修改的结构化 Provider；不向 PTY 注入提示词。
- 绑定时由本机确认会话工作区确为该项目；页面 URL 不能直接授予目录权限。
- 同一会话中的人工输入和反馈共享执行仲裁；不能仅串行化反馈而忽略人工轮次。
- 同一工作目录中的专用会话和其他会话不能无协调地并行修改。
  独立会话不是独立工作区；worktree 隔离如需引入，须另行设计预览与合并流程。
- 反馈绑定失效、会话结束或设备离线时保留反馈并明确提示，不自动创建替代会话。
- 新建专用会话需本机授权，并明确 Provider、目录、审批和停止规则；
  不因为叫“专用会话”就默认复用自动审批的外部 AI Runtime。

## 7. 执行与可靠性要求

- 首版建议提交反馈不直接改代码，由开发者确认内容、目标会话和修改范围。
- 反馈 ID、执行尝试 ID、命令 ID 和 AI 轮次 ID 分别关联；提交重试不得重复执行。
- 网络 ACK、命令接收与 AI 轮次成功是不同状态，不能用前者代替后者。
- 超时、断线或重启后按已保存标识对账；结果未知时不自动换 ID 重发修改任务。
- 显示反馈采集时版本及修改完成时版本；无法取得版本则明确未知，不伪造一致性。
- 业务方看到的状态和结果应经过筛选，不默认开放完整项目对话、终端或审批权限。
- 取消提交、取消待执行反馈、停止正在执行的 AI 轮次需要区分，具体交互待定。
- 保留反馈到执行及验收的关联；存储位置、文本容量和清理周期待定。

## 8. 首轮验证与建议实施阶段

### 阶段 A：仅验证预览访问

- 在开发者电脑启动受限 CONNECT 代理，使用 Chrome 插件或等价受控代理配置验证。
- 从另一台电脑访问原域名，完成自身账号登录和典型页面操作。
- 验证至少两个已授权项目端口、接口、静态资源及实际使用的 WebSocket / HMR。
- 未授权端口及域名被拒绝；非目标流量保持预期路径；停用后恢复代理设置归属。
- 页面访问不要求改业务方 hosts，不增加页面 HTTPS 服务。

### 阶段 B：反馈与人工处理

- 按第 4 节实现反馈入口、选元素、整页反馈、文字提交及反馈记录，开发者能查看并处理。
- 插件使用受限凭据，不直接调用通用 AI API，也不获得任意会话控制权限。
- 先确认文字与元素上下文的反馈流程有用，不将准确源码定位作为已实现前提，不涉及截图。

### 阶段 C：已有或专用会话执行闭环

- 在明确会话策略后，实现授权绑定、确认执行、串行仲裁和状态关联。
- 验证忙碌、离线、绑定失效、重复提交及未知结果不会导致串会话或重复修改。
- 业务方能查看修改后环境并确认验收；执行完成不会自动标记已验收。

暂不纳入首版：手机扩展、自研浏览器、多开发者不同域名、同 Profile 同域名按标签页分流、
截图及 AI 看图、全功能浏览器自动化、未经授权的跨网访问和自动提交 / 发布代码。

# 快捷任务：开发流程与技术方案

## 边界与交互

快捷任务由 Mac 用户在 App 中创建、编辑和删除。定义包含名称、说明、工作目录、
Shell 脚本、代理模式及执行前确认开关；完整定义只存放在这台 Mac。
Web 和手机只收到设备 ID、工作区不透明 ID、名称、说明、代理模式和版本，
不能上传或修改脚本、工作目录或代理地址。代理环境从现有
`TerminalEnvironment.make(proxy:)` 构造，按本次进程固定，不修改其他终端。

桌面工作台提供“快捷任务”入口；手机底栏提供“快捷”Tab。
按钮先确认目标设备与工作区，然后生成一次运行。运行输出、状态和退出码可查看，
运行中可取消；离线时不能启动。Mac 在管理页可试运行、停止、编辑和删除。
首版不接受运行时参数，也不执行交互式 TUI；需要凭据的脚本应在 Mac 本地安全获取，
不要将密钥写在脚本、Server 元数据或终端输出中。
运行输出会在 Server 保留有限时间，部署脚本应避免回显令牌或凭据。
执行使用 `/bin/zsh -f -c`，不加载用户 Shell 配置，避免启动文件覆盖每次任务的
代理设置；命令需要的环境变量应自行在本地配置或由可执行文件的绝对路径提供。

## 执行与同步

1. Mac 本地原子保存定义并将**完整元数据快照**经设备 WebSocket 发布；
   每次编辑提高版本号。Server 保存快照，但不保存命令或代理地址。
2. 浏览器用随机运行 ID 发起 REST 请求。Server 校验设备在线、定义版本和同一任务
   没有待执行运行，持久化运行记录，然后仅向对应 Mac 转发任务 ID、版本和运行 ID。
   相同运行 ID 重试只返回已有记录，不重复执行。
3. Mac 再次校验本地定义和版本，创建独立、非登录 Shell 子进程；报告运行中、
   有界输出快照及最终退出码。进程结束后保留运行记录，而不保留进程。
   取消只向这个运行的进程发送终止请求；收到最终状态前不显示“已取消”。
   首版固定 15 分钟超时，超时会终止进程组并显示失败；Mac 退出时也清理自己启动的进程组。
4. Web 轮询运行记录，断开页面后仍可重新查询。断连不能自动重新执行部署；
   Server 应明确标记中断，并要求用户手动重新发起。

Server 只保存最近 30 天的已结束运行，启动和每日清理一次；运行中的记录不会被过期
清理。上线新版本前按 [Server 发布流程](SERVER_RELEASE.md)运行数据库 migration，
再启动包含新协议的 Server 和 Mac App。断连时运行结果显示“未知，需人工核实”，
即使 Mac 子进程可能仍在执行，也不会自动重试部署。

PTY 会话和 ACP 会话不接收快捷任务命令。新协议定义在
`packages/contracts/events/`，生成文件由脚本维护。Server 新持久化结构必须使用
显式 TypeORM migration；数据库凭据及本地路径都不进入浏览器。

## 实施顺序和验收

先建立契约和 Server 的设备鉴权、版本/幂等/并发边界；再实现 Mac 本地存储、
配置表单与独立进程；最后接入桌面和手机入口。覆盖成功、失败、取消、离线、
重复点击、代理禁用与自定义、重连及敏感字段不上传的测试。
完成后运行契约、Server、Web、Mac 检查和仓库跨包检查。
